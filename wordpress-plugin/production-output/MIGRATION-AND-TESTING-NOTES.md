# Migration and Testing Notes — Crescent Visibility Interactive (Production)

Generated by Claude from the production prompt (v3 + v4 synthesis).

## Schema & Upgrade

- The plugin now records `cvi_schema_version` on activation.
- `includes/interactive.php` performs version-gated `dbDelta` auto-upgrade for the new columns (`q_at_best`, `moon_age_at_best`, `data_version`) and indexes.
- **For existing installs**: Re-importing the JSON is still the safest and recommended path (it uses `REPLACE` on the natural key). The auto-upgrade will add the columns, but it will not backfill historical `q_at_best` / `moon_age_at_best` values.

## How to Verify After Install

1. Upload and activate `crescent-visibility.zip`.
2. Go to **Tools → Crescent Visibility** and import the bundled data file (or any generated JSON).
3. Add to a page:
   ```html
   [crescent_visibility_interactive]
   ```
   (or `[crescent_visibility_point theme="dark"]`)
4. Publish and view:
   - City selector should default to Jerusalem + the next new moon.
   - Year and new moon dropdowns should be populated.
   - Moving the atmospheric sliders should live-update the three result cards.
   - A small context map should appear.

For deeper validation (real AJAX round-trips, Leaflet behavior, slider debouncing), use your browser DevTools and the checklist below.

## Key Fidelity & Security Improvements

1. **Exact heuristic port** from `main.go:applyAtmosphericAdjustment`
   - `J` / `?` / unmapped values now resolve to value 0 → floored to 1 (E). No early return inside the function.
   - Bad-window threshold is `age > 100` (matches the web app), not 80.
2. **AJAX security**
   - All AJAX handlers validate nonces.
   - Proper sanitization + validation on city/year inputs.
3. **Asset paths**
   - Fixed `plugin_dir_url()` bug (was passing a directory instead of a file).
4. **Styling & markup**
   - Moved from heavy inline styles to proper CSS classes + `data-theme="dark"`.
   - Server-rendered `<noscript>` fallback.
5. **Frontend robustness**
   - `AbortController` + per-(city,year) caching.
   - Graceful Leaflet CDN failure handling.
   - Debounced live updates.
6. **Colors**
   - Effective category colors now exactly match the web app Tailwind palette.

## Testing Checklist (DevTools + Manual)

### 1. Basic Shortcode Rendering
- Drop `[crescent_visibility_interactive]` on a page with Jerusalem as default.
- Verify it loads the smart default (closest/next new moon for Jerusalem).

### 2. AJAX Flow (most important)
1. Open DevTools → Network tab.
2. Change City → should fire `cvi_get_years`.
3. Change Year → should fire `cvi_get_newmoons`.
4. Confirm both endpoints return 200 and include the nonce in the request.
5. Verify the new moon dropdown populates with real data (including `q_at_best` and `moon_age_at_best`).

### 3. Atmospheric Adjustment (Live)
- Move the cloud cover and transparency sliders.
- Confirm the three result cards update **live** (debounced) with correct Effective values.
- Test edge cases:
  - Cloud = 100% + low transparency → should degrade categories significantly.
  - High transparency (9–10) → slight improvement possible.
- Verify "J" / bad windows show the correct "Not a reliable crescent window" message.

### 4. Card Fidelity
- Each card should show:
  - Large Effective letter with correct color
  - Raw value
  - Age (h) • Q (3 decimals) when available
  - Correct plain-English note
- Compare a few dates against the original web app `/point` tool for the same location + conditions.

### 5. Dark Theme
- Add `data-theme="dark"` to the root container (or use the class) and verify the zinc dark variant renders correctly.

### 6. No-JS Fallback
- Disable JavaScript and reload the page.
- You should see server-rendered fallback cards for the default new moon.

### 7. Admin / Import
- Go to Tools → Crescent Visibility.
- Confirm the page now documents the new interactive shortcode attributes and the re-import recommendation for historical Age/Q data.

## Known Limitations / Future Work

- The interactive experience still relies on the 13 locked cities. Adding arbitrary custom locations would require either:
  - Live calls to the renderer (violates minimal-footprint goal), or
  - Precomputing a much larger dataset.
- No "likelihood over 10 years" visualization yet (can be added later as an optional panel using `crescent_yearly_summary` if populated).

## Rollout Recommendation

1. Deploy the new files.
2. Tell existing users: "Re-import your JSON if you want Age + Q values in the interactive cards."
3. The auto-upgrade will prevent fatal errors on old databases.
